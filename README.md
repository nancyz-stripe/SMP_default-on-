# Managed Payments default-on — prototypes

A Vite + React + TypeScript app holding the SMP default-on prototypes. It was
28 standalone HTML files, each a whole document with its own `<style>` and
`<script>`; every one of them is now a routed page.

```
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck, then build to dist/
npm run typecheck
```

## Routes

| Path | What it is |
| --- | --- |
| `/gallery` | The index, with live previews of each prototype |
| `/website`, `/pricing` | The stripe.com pages the flow starts from |
| `/onboarding/:step` | The onboarding flow with the cross-border stretch in it |
| `/dashboard`, `/account-app/:page` | Where that flow lands, and the activation overlay |
| `/smp-home/:stage/:tab` | SMP Home, at any of its three stages |
| `/flow`, `/flow-2step` | The archive flows |
| `/smp` | The merged SMP screen, with its control panel |
| `/treatments` | Eleven treatments for the flow's last two steps |
| `/email/first-payment`, `/email/tax-threshold` | The two emails |
| `/globe-prototype` | The globe playground the other globes were copied from |
| `/v/:slug` | The v1–v8 archive, by original filename |

These are the paths the old static build served, so existing links still
resolve.

## How the port is laid out

```
src/
  components/   shared across prototypes: the wordmark, the fee badge, the
                dashboard shell, the upgrade choreography
  globe/        one three.js scene, parameterised — see below
  flow/         what the two archive flows share
  pages/<Name>/ one directory per prototype: index.tsx and styles.css
```

**Styles are scoped per page.** Every prototype declared `* { margin: 0 }`,
`body {}` and its own `:root` tokens, and they reuse class names freely, so
bundling them globally would cross-contaminate. Each stylesheet is wrapped in a
`.page-<slug>` root using CSS nesting, with `body`/`:root`/`*` rewritten and
`@keyframes` hoisted and prefixed. **Class names are untouched** — the isolation
comes from the wrapper, not from renaming anything.

Those stylesheets are generated by `scripts/extract.mjs`, a one-shot porting aid
that split each original into its CSS, its markup and its script. It isn't part
of the build and doesn't need to run again; `.prettierignore` keeps formatting
off the files it produced so a re-run wouldn't churn them.

**One globe.** The three.js scene was copied into 15 files, differing only in
radius, light palette, dot darkening, and whether value cards float over it. It
is now a single module with those as options, plus three variants the copies had
grown: a coverage wave (v4), fixed routes instead of random arcs (treatments),
and live colours (the playground).

Porting it from r128 to 0.186 needs two deliberate opt-outs to keep the original
look, both documented where they're set in `globe/createGlobe.ts`:

- **Colour management off.** r128 fed colours to the GPU as authored; modern
  three converts sRGB to linear and back, which lightens every colour here.
- **Point lights at `decay: 0`.** These lights sit thousands of units away and
  were written for r128's non-physical lighting. Modern three always applies
  decay, so at the default the globe would be lit by ambient light alone.

## Known issue carried over

`/v/v4-latest` has an inverted region mapping: its shader reads `a_region` as
`0 = home`, and the sampling feeds it `0` for home dots, so under "Cross-border
only" it lights the home market and dims the rest of the world — backwards from
what its own comments describe. It's pre-existing, and fixing it would change
how the prototype looks, so it's preserved and flagged rather than quietly
altered.
